<h1>🧪 DivinityEconomy 4.0.0-arclight (26.2) – Experimental 🧪</h1>
<p><b>This is an experimental build for hybrid servers (Arclight and similar).</b> It is the 4.0.0 release plus modded item support, published as a separate jar so it can be tested without affecting the main release. It is not a replacement for <code>DivinityEconomy-4.0.0.jar</code> until it has been proven on a real hybrid server.</p>

<h2>📦 Build Details</h2>
<ul>
    <li><b>Jar:</b> <code>DivinityEconomy-4.0.0-arclight.jar</code></li>
    <li><b>Plugin version (<code>plugin.yml</code> / Maven):</b> <code>4.0.0-arclight</code>. This is the version shown by <code>/plugins</code>, in the startup banner, via PlaceholderAPI and on bStats.</li>
    <li><b>Plugin name:</b> still <code>DivinityEconomy</code>, so the data folder, permissions, placeholders and <code>depend</code> entries of other plugins are unchanged. <b>Do not run this jar alongside the normal one</b>; they are the same plugin.</li>
    <li><b>Config version (<code>Main.Version</code> in <code>config.yml</code>):</b> still <code>4.0.0</code>. This is the config schema version used by the migration system, which only understands numeric versions, so it must not carry the label.</li>
    <li><b>Based on:</b> 4.0.0 (Minecraft 26.2, Java 25 required).</li>
    <li><b>Source:</b> branch <code>experiment/arclight-modded</code>, built on YouniorPL's "Arclight Patch" (#79).</li>
</ul>

<h2>⚠️ Upgrade Notes ⚠️</h2>
<ul>
    <li>Back up your plugin folder first. The plugin will add entries to <code>materials.yml</code> and <code>materialAliases.yml</code> and a <code>Commands.Admin.Modded</code> setting to <code>config.yml</code>.</li>
    <li>You can go back to the normal jar. Imported modded entries are left in <code>materials.yml</code> and are harmless on a server that doesn't have those materials (they are skipped).</li>
    <li>On servers that do not expose modded materials to Bukkit (plain Paper/Spigot) this build behaves like 4.0.0; the scan finds nothing.</li>
</ul>

<h2>➕ What's New ➕</h2>
<ul>
    <li>
        <h4>Modded Item Import</h4>
        <p>About 10 seconds after startup (hybrid servers register mod items late), and whenever an admin runs <code>/modded</code>, the plugin scans for materials outside the <code>minecraft</code> namespace and adds new ones to <code>materials.yml</code>.</p>
        <ul>
            <li>New items are imported <b>banned</b> (<code>ALLOWED: false</code>) with <code>QUANTITY: 0</code>. Nothing is tradable until you set it up, e.g. <code>/banitem &lt;item&gt; false</code> plus <code>/setstock</code> and <code>/setvalue</code>.</li>
            <li>A short alias is created automatically (<code>cobblemon:mago_berry</code> becomes <code>mago_berry</code>). Aliases never replace an existing alias or item.</li>
            <li>Entries already in <code>materials.yml</code> whose mod wasn't loaded yet are skipped, then picked up by the next scan with their settings intact.</li>
            <li>Unresolved materials are never in the market, so they can't be bought or sold.</li>
            <li>Only blocks/items are supported. Modded potions, entities and enchants are not.</li>
        </ul>
    </li>
    <li>
        <h4><code>/modded</code> Command</h4>
        <p>Rescans for modded items on demand. Setting: <code>Commands.Admin.Modded</code>. Permission: <code>de.admin.modded</code> (operators by default, included in <code>de.admin</code>).</p>
    </li>
    <li>
        <h4>Localisation</h4>
        <p>All modded-item messages are available in all 20 languages. The translations are machine-generated and should be reviewed by native speakers.</p>
    </li>
</ul>

<h2>🛠️ Changes From The Original Patch 🛠️</h2>
<ul>
    <li>Strict item validation: no stone placeholder for unresolved modded items.</li>
    <li>Only the block/item manager imports modded items; the potion and entity managers no longer run the scan.</li>
    <li>Dotted IDs such as <code>mod:item.v2</code> are stored as <code>mod:item_v2</code> (the real ID is kept in <code>MATERIAL_ID</code>) so Bukkit doesn't split them into nested sections. Colliding keys are skipped and logged.</li>
    <li>Imported items and aliases are preserved across reloads and restarts. <code>ConfigUpdater</code> removes any key that isn't in the bundled files on every load, which would otherwise wipe them.</li>
    <li>Alias saving is serialised and goes through the Bukkit scheduler instead of a raw thread.</li>
    <li>The ConfigUpdater dependency is kept, and the original patch's version bump and committed IDE files are dropped.</li>
</ul>

<h2>🧪 Testing Status 🧪</h2>
<ul>
    <li>Automated: the full suite (178 tests) passes. A simulated hybrid server (a fake modded-material provider) covers import, aliases, dotted IDs, collisions, late-loading mods, <code>/banitem</code>, potion/entity isolation and reload survival.</li>
    <li><b>Not yet verified on a real Arclight server.</b> The simulation checks this plugin's logic, not how Arclight populates Bukkit's material registry.</li>
</ul>

<h3>Please test</h3>
<ol>
    <li>Start with a few mods installed. About 10 seconds after startup, check the console for "Importing modded material" lines.</li>
    <li>Confirm <code>materials.yml</code> and <code>materialAliases.yml</code> contain the new entries (banned, quantity 0).</li>
    <li>Enable one with <code>/banitem &lt;alias&gt; false</code>, set stock and price, then buy and sell it.</li>
    <li>Restart and confirm the entries, settings and aliases are still there.</li>
    <li>Add another mod, run <code>/modded</code>, and confirm only the new items are imported.</li>
</ol>

<h2>⚠️ Known Limitations ⚠️</h2>
<ul>
    <li>Imported items have no stock or price until an admin sets them (the Static pricing model also needs <code>PRICE</code>). They use the default <code>ELASTICITY</code> of 0.7.</li>
    <li>The server software must expose modded items through Bukkit's <code>Material</code>.</li>
</ul>
